# Purpose

The HELIX Specification is the authoritative description of the Organizational Engineering discipline.

It defines the principles, architecture, standards, object models, governance, and reference structures used to design, build, operate, and continuously improve AI-native organizations.

This document serves as the entry point to the complete HELIX ecosystem.

---

# Scope

The HELIX Specification governs:

- Foundation
- Architecture
- Engineering Standards
- Organizational Architecture
- Knowledge Architecture
- Behavior Architecture
- Execution Architecture
- Learning Architecture
- Reference Implementations

---

# Philosophy

HELIX is based on one central belief:

> Organizations should be engineered as living systems of purpose, knowledge, behavior, governance, and continuous learning.

Everything within HELIX exists to support that philosophy.

# Governance

The HELIX Specification is governed by the HELIX Foundation.

Changes follow the Architecture Decision Record (ADR) process.

Major structural changes require review before adoption.

---

# Versioning

The HELIX Specification follows semantic versioning.

Major versions introduce architectural changes.

Minor versions introduce new standards or capabilities.

Patch versions clarify or correct existing specifications.

---

# Guiding Statement

The HELIX Specification defines the discipline of Organizational Engineering.

It is independent of any programming language, AI model, software platform, or implementation technology.

Its purpose is to provide a stable foundation upon which future organizations can be engineered.

## Organizational Modes of Work

Status: Candidate Discovery

HELIX currently recognizes four candidate modes of organizational work:

- Know
- Think
- Do
- Improve

These modes are not yet frozen standards. They are being evaluated as a candidate meta-architecture for classifying future HELIX capabilities.
