## B. Historical context — success-state diagnosis (25 September 2026)

*Context only, for traceability. Chat-record diagnosis, not separately filed as a HELIX artifact.*

**Observations (production, 25 September 2026):**

- `page-private-dining.php` and `build/style-dining-index.css` (from website commit `0301a30`) had been uploaded to production; the smoke test passed and the integrated enquiry form rendered.
- An owner-approved controlled production submission delivered the enquiry email to `info@konnichiwa.nl`. After submission the visitor landed on `/private-dining/` with no visible success confirmation, and `private_dining_enquiry` was not observed in Tag Assistant.
- The production access log for a subsequent controlled submission showed `POST /wp-admin/admin-post.php` → HTTP 302, followed by `GET /private-dining/?dining_inquiry=success&receipt=<64-hex token>` → HTTP 200.
- The production `functions.php`, downloaded by the Case Owner, had SHA-256 `98c295a36a8e95af8d8cda4bb07cc586046ef865f914cab5dde872ae9594c464`, byte-identical to the website repository version.
- After manually scrolling to the enquiry section, the Case Owner confirmed that "Bedankt voor je aanvraag!" was present.

**Excluded as evidence:** access-log entries for `GET /private-dining/?dining_inquiry=success&receipt=not-a-valid-token` (→ 302) and the adjacent plain and `?dining_inquiry=error` requests at 12:13 on 25 September 2026 were read-only diagnostic probes, not a form submission, and are not used as evidence for any submission.

**Inference from code and evidence:** in the repository implementation, a well-formed success URL returns HTTP 200 only when the one-time receipt is consumed and the success state is rendered; every failure branch returns a 302. The confirmation is rendered inside `#private-dining-enquiry`, far below the fold, and the success redirect carried no fragment or scroll behaviour.

**Conclusion (proven, 25 September 2026):** the defect was UX/navigation, not backend processing — the server-confirmed success notice was rendered, but outside the visitor's initial viewport.
