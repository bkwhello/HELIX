## C. Hardening rationale

A pre-merge audit of this existing production code identified three bounded input-robustness issues:

1. Non-string/array input for `pd_email` could trigger a `TypeError` under PHP 8.4 before controlled validation ran.
2. `absint()` could coerce invalid group-size input — negative, suffixed, or decimal values — into an apparently valid number.
3. Receipt-token consumption checked for hex characters but did not explicitly enforce the protocol contract of exactly 64 lowercase hex characters.

This was existing production code, and was therefore treated as a separate, individually attributable hardening change rather than folded into the original reconciliation.
