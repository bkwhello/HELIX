## C. Root cause

**Observed:**

- Page 75 (English) owns the slug `catering`.
- Page 224 (Dutch) uses the slug `catering-2`.
- `/catering/` redirects via Polylang to `/en/catering/`.
- `/catering-2/` serves page 224 directly; `/en/catering/` serves page 75 directly.
- The Polylang translation relationship itself is correct (section B).

**Inference:** the most strongly supported explanation is **historical slug ownership** — the older English page (75) retained `catering`, requiring the later Dutch page (224) to use a unique slug. Supporting context: a local database dump of November 2025 shows page 75 as the only catering page, then assigned to `en`; the same `-2` pattern appears for other translated pages (e.g. `/en/about-us-2/`, `/en/private-dining-2/`). It is **not** independently proven here that the installed Polylang edition itself produced the exact `-2` value; WordPress page configuration was not inspected in the admin.

## F. Theme code references

*Source: website repository `github.com/bkwhello/konnichiwa` at `106016c48dbf2e3a08f610d534e21bd042e57bc9`.* Not fixed by this observation.

1. `template-parts/home-nl.php` (line 77) — the NL homepage catering card links to `home_url('/catering/')`, which currently **crosses from Dutch to the English Catering page** via the Polylang redirect.
2. `page-catering.php` (line 8) — the configured `canonical` value is `home_url('/catering/')`. Rank Math currently emits the correct live canonical (`/catering-2/`), so no current canonical-indexing defect is claimed from this theme value alone.
3. `page-catering.php` (line 263) — the JSON-LD `url` is `https://www.konnichiwa.nl/catering/`, which does not match the current NL page URL (`https://konnichiwa.nl/catering-2/`); it appears in the live NL page HTML.
4. `functions.php` (Catering handler, line 1222) — the redirect fallback is `home_url('/catering/')`, relevant only when the normal referer is unavailable.

## G. Separate discovery — page sitemap language coverage

**Observed:** the inspected page sitemap (`https://konnichiwa.nl/page-sitemap.xml`, 22 entries, latest `lastmod` 2026-09-12) listed many EN URLs (including `/en/catering/`), while several expected NL URLs — including `/catering-2/`, `/omakase-utrecht/` and the NL homepage `/` — were absent; `/private-dining/` was present.

This is recorded as a **broader discovery**, not part of the Catering routing root cause. It is not diagnosed or repaired here and **requires a separate read-only SEO/indexation audit** before any remediation.

## H. Remediation status

**Remediation is NOT YET APPROVED.** The Case Owner has not selected a final URL strategy, and none of the options below is an approved decision. The next decision gate must compare at least:

1. retaining `/en/catering/` and giving the NL page a clean Dutch canonical URL;
2. transferring `/catering/` to the NL page and changing the EN slug;
3. a shared-slug capability, if technically and licensing-wise appropriate.

That decision must consider SEO/indexation effects and the required redirects (including `/catering-2/` and `/catering/`) before any implementation, and would be followed by separately gated WordPress configuration and website code changes (section F).
