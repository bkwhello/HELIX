# O-021 — Validation and Production Verification of `reservation_widget_open` Listener
---

Status: **Collected — Production Verified (28 August 2026, Test 5).** Records the full validation arc of the `reservation_widget_open` listener (`Listener - Guestplan widget open` Custom HTML, `Reservation widget open` Custom Event trigger, `GA4 - Event - reservation_widget_open` tag, `Window Loaded - All Pages` trigger): three GTM Preview tests (Tests 1–3), a clean non-Preview production test that surfaced a GA4-receipt gap (Test 4), a root-cause finding that the implementation existed only in the unpublished GTM workspace during Test 4, and — following GTM Version 8 publication — a clean, non-Preview production test with confirmed GA4 Realtime receipt (Test 5). Per the same two-tier standard applied to `reservation_click`/`phone_click`/`directions_click` (O-018/O-019/O-020), both legs (GTM Preview validation and GA4 production receipt) are now satisfied.

This observation follows an extended prior diagnostic sequence (chat-record only, not separately filed as HELIX artifacts) that identified the deterministic open condition (`#gstpln-widget-host`'s open ShadowRoot containing `.gp-widget--body`) after several superseded hypotheses (iframe rendering, DOM-selector, load-time-churn), and investigated one unresolved GTM Preview anomaly (a single `reservation_widget_open` reported immediately after a page reload with no deliberate open), which was explicitly logged as **UNEXPLAINED / NOT REPRODUCED**. That anomaly is **not** claimed as resolved by this observation, including by Test 5's production PASS below — see "What this does not establish."

## Test 1 — Clean/reconnected Preview, no widget interaction

- **Action:** GTM Preview (re)connected; no reservation CTA clicked, no widget interaction of any kind.
- **Observed:** `Listener - Guestplan widget open` activated exactly 1 time (its own initialization); `GA4 - Event - reservation_widget_open` **not activated**; no `reservation_widget_open` event appeared in the Tag Assistant event stream.
- **Verdict: PASS** — listener initialization alone does not produce a false `reservation_widget_open` event under this test's conditions.

## Test 2 — First genuine Guestplan widget opening

- **Action:** "RESERVEER EEN TAFEL" clicked exactly once.
- **Observed:** `reservation_widget_open` appeared exactly once in Tag Assistant; `GA4 - Event - reservation_widget_open` activated exactly 1 time; `GA4 - Event - reservation_click` activated exactly 1 time (confirming both events fire independently for the same interaction, as designed); `Listener - Guestplan widget open` remained activated exactly 1 time (no re-initialization).
- **Verdict: PASS** — one genuine widget opening produces exactly one `reservation_widget_open` event.

## Test 3 — Close and reopen

- **Action:** widget closed; ~2 seconds elapsed; "RESERVEER EEN TAFEL" clicked exactly once more.
- **Observed:** `reservation_widget_open` appeared a second time; `GA4 - Event - reservation_widget_open` activated 2 times total (cumulative); `GA4 - Event - reservation_click` activated 2 times total (cumulative); `Listener - Guestplan widget open` still activated exactly 1 time — the same persistent listener instance correctly detected two separate genuine openings without re-initializing or duplicating.
- **Verdict: PASS** — the closed→open→closed→open cycle produces exactly one event per genuine opening, confirmed across a real reopen, not merely a single occurrence.

## Test 4 — Real production interaction, non-Preview (28 August 2026)

- **Action:** GA4 Realtime first allowed to clear (0 active users, no current events). Test performed on the normal production website, outside GTM Preview/Tag Assistant. Reservation CTA clicked deliberately; Guestplan reservation interface opened.
- **Observed (first Realtime check):** active users: 1; `page_view`: 2; `user_engagement`: 2; `reservation_click`: 1; `session_start`: 1; `reservation_widget_open`: **absent**.
- **Observed (after waiting and rechecking):** active users: 1; `page_view`: 2; `reservation_click`: 2; `user_engagement`: 2; `session_start`: 1; `reservation_widget_open`: **still absent**.
- **Verdict: GA4 production receipt NOT OBSERVED.** `reservation_click` reached GA4 twice in the same window, confirming the production interaction occurred and that GA4 itself is receiving events end-to-end for at least one sibling event. Short Realtime latency is not a sufficient explanation given the repeat check. The exact failing layer (unpublished GTM configuration vs. trigger/tag misconfiguration vs. consent vs. GA4-side filtering) is **not yet established** — see the companion investigation for hypothesis analysis. The second `reservation_click` count is not, by itself, treated as evidence of a duplicate `reservation_click` implementation; its origin is not established by this test.
- **This does not downgrade Tests 1–3.** Those remain valid GTM Preview evidence. This test isolates a distinct question: whether the currently *published* GTM container reproduces that Preview behavior in production. It does not.

## Test 5 — Root cause confirmation, GTM Version 8 publication, clean post-publish production validation (28 August 2026)

- **Pre-publish audit (read-only):** verified the dependency chain `Window Loaded - All Pages → Listener - Guestplan widget open → dataLayer.push({event:'reservation_widget_open'}) → Reservation widget open (Custom Event trigger) → GA4 - Event - reservation_widget_open → G-C29ZMF288W`. Listener behavior confirmed as designed: open-state detected via `#gstpln-widget-host` shadow root's `.gp-widget--body`; `wasOpen` baseline does not emit on attach; fires only on closed→open transition; 150ms debounce; polling stops on attachment or after 10s; no second/duplicate measurement path identified. Verdict: **PASS — Ready for controlled publish.** Diagnostic instrumentation (`console.log`, `window.__gp10`) noted present and explicitly treated as non-blocking — not removed as part of this step.
- **Root cause, confirmed:** during Test 4, the four objects (`Listener - Guestplan widget open`, `Reservation widget open` trigger, `GA4 - Event - reservation_widget_open` tag, `Window Loaded - All Pages` trigger) existed only in the Default Workspace, never published. GTM Preview always reads the workspace, so Tests 1–3 passed; normal production traffic was still served by **published Version 7**, which did not contain these objects — explaining Test 4's clean production interaction with no `reservation_widget_open` receipt while `reservation_click` (published since Version 5) succeeded twice in the same window. This directly confirms the leading hypothesis (H1/H2/H3) from the companion investigation, and directly explains the "Wijzigingen in werkruimte: 4" observation that motivated it.
- **Publication:** Case Owner authorized publish after the audit PASS. **GTM Version 8**, "GA4 reservation_widget_open tracking" — "Adds Guestplan widget-open detection and GA4 reservation_widget_open event tracking" — published 28 August 2026. Version 8 contains 7 tags / 6 triggers; the Version 7→8 delta is exactly the four objects listed above. No unrelated configuration intentionally changed.
- **Post-publish production validation:** GTM Preview/Tag Assistant explicitly **not connected** ("Niet verbonden"); normal production website; Guestplan widget deliberately opened. GA4 Realtime showed `reservation_click = 1`, `reservation_widget_open = 1`.
- **Verdict: PASS — Production Verified.** The full chain — production interaction → Guestplan Shadow DOM closed→open detection → `dataLayer` push → GTM Custom Event trigger → GA4 event tag → GA4 Realtime receipt — is now evidenced outside Preview, on the published container.

## Engineering conclusion, scoped precisely

Tests 1–3 (Preview): 0 genuine opens → 0 events; 1 genuine open → 1 event; 2 genuine opens → 2 events, no false positives under tested conditions. Test 4 (production, pre-publish) isolated a genuine GA4-receipt gap. Test 5 (production, post-publish) both explains that gap — unpublished workspace state, root-caused precisely — and closes it via GTM Version 8.

**Classified as: `Website/Guestplan state transition → GTM listener → reservation_widget_open dataLayer/custom event → GA4 event tag firing` — VALIDATED IN GTM PREVIEW AND PRODUCTION VERIFIED (GTM Version 8, 28 August 2026).**
